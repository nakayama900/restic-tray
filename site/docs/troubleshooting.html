Troubleshooting

Diagnose and resolve common issues with SmartScreen, Windows Startup, DPAPI credentials, Cloudflare R2 permissions, repository locks, excludes, and MCP policies.

Use the summary table below to jump directly to the cause and fix for common installation, Cloudflare R2, DPAPI, lock, and MCP issues.

Symptom-to-fix quick reference
Symptom Cause Immediate Fix
SmartScreen / Smart App Control warning Initial v1.0.0 releases are unsigned Verify SHA256SUMS.txt + gh attestation verify, then click More info → Run anyway (or build from source).
Backups paused after Windows reboot No automatic startup registration yet Add restic-tray.exe --minimized shortcut inside shell:startup.
credentials.dat decryption error DPAPI is tied to the original PC and Windows user Re-enter R2 keys and original repository password under Settings → Credentials.
403 AccessDenied on bucket delete Bucket-scoped Object Read & Write token lacks DeleteBucket Objects are already emptied; delete the empty bucket in Cloudflare Dashboard.
Backup refused (exclude matches target) Active exclude pattern covers the target path itself Rename/move parent folder, edit excludes, or turn off useBasicExcludes.
History shows deferred Repository locked by another process/PC (exit code 11) Wait for automatic 15-min retry (up to 2 retries) or unlock stale lock once idle.
MCP destructive tool rejected Opt-in flag is false or confirmation missing Enable allowPrune / allowDeleteStorage / allowHandoff and pass dryRun: false + confirmation.
Removed Google Drive startup error Legacy "storageBackend": "googleDrive" in config.json Remove that key, configure Cloudflare R2, and restart.

Windows SmartScreen or Smart App Control blocks the installer

Cause: Initial v1.0.0 releases are distributed unsigned.

  • First verify the installer using SHA256SUMS.txt and gh attestation verify (verification guide).
  • On the SmartScreen dialog (“Windows protected your PC”), click More info → Run anyway.
  • If Windows 11 Smart App Control is enforced on your machine, unsigned executables are blocked by Windows policy; you can instead build locally from source with Rust (see Build from Source).

Scheduled backups stopped after restarting Windows

Cause: Restic Tray does not auto-register a Windows Startup entry yet. Scheduled backups and overdue alerts run only while the tray app is running.

Fix: Press Win+R, open shell:startup, and create a shortcut to "%LOCALAPPDATA%\Programs\Restic Tray\restic-tray.exe" --minimized.

Credentials fail to decrypt (credentials.dat error)

Cause: config\credentials.dat is protected with Windows DPAPI tied to the exact Windows user and machine. Copying it to another PC, reinstalling Windows, or corrupting the file makes decryption fail. Restic Tray intentionally stops with a clear error rather than silently overwriting the file.

Fix: Re-enter your Cloudflare R2 Access Key ID, Secret Access Key, and original Restic repository password under 設定 → 認証情報 and click 認証情報を保存. If the original file is corrupt and cannot be partially updated, back up or remove %LOCALAPPDATA%\io.github.nayuengin.restic-tray\config\credentials.dat and save all three values again.

Cloudflare R2 connection errors or 403 AccessDenied

  • Check Account ID & Bucket: Verify the 32-character Account ID (no spaces or slashes) and exact lowercase bucket name. Confirm the generated URL under 設定 → 保存先 matches s3:https://<accountId>.r2.cloudflarestorage.com/<bucket>[/<prefix>].
  • Token expired or scoped to wrong bucket: Check your R2 API token in Cloudflare Dashboard under Manage R2 API Tokens to confirm it has Object Read & Write permission for this bucket and has not passed its TTL.
  • 403 AccessDenied during entire-bucket deletion: A bucket-scoped Object Read & Write token can empty every object and abort incomplete multipart uploads, but Cloudflare reserves DeleteBucket for Admin Read & Write tokens. After Restic Tray reports the bucket is emptied, delete the empty bucket container in the Cloudflare Dashboard.

Backup refused because an exclude pattern matches the target folder

Cause: Restic Tray checks whether any active exclude pattern covers the target path itself (for example placing a backup target inside a folder literally named D:\target\my-project, which matches the built-in target/ exclude).

Fix: Either move/rename the parent folder, adjust your custom globalExcludes / target excludePatterns, or turn off 基本の除外パターンを有効にする on the フォルダ screen.

Backup status shows deferred (repository locked)

Cause: Another operation or PC holds an exclusive lock in the Restic repository (restic exit code 11 during --retry-lock).

  • Scheduled backups automatically record status: "deferred" and retry after 15 minutes (up to 2 automatic retries).
  • If a previous process crashed and left a stale lock behind, wait a few minutes and ensure no other PC is actively pruning/checking, then use the app’s safe unlock action (or restic unlock via CLI).

Unity project files or multi-PC handoff warnings

  • Library/ missing from snapshot: Expected when useBasicExcludes is enabled. Turn it off on the フォルダ screen only if you genuinely need generated caches uploaded.
  • Multi-PC handoff blocked by Temp\UnityLockfile or .git: Close the Unity Editor before releasing or taking over a shared project. Folders containing .git cannot use projectKey handoff; sync Git repositories with Git instead.

MCP tool call rejected or cannot connect

  • Destructive tool blocked: forget_prune, update_retention_policy, autoPruneAfterBackup, delete_r2_bucket, and takeover_project are disabled by default. Enable the specific opt-in flag (agent.allowPrune, agent.allowDeleteStorage, or agent.allowHandoff) in config.json or Settings, and supply explicit confirmation fields with dryRun: false.
  • Empty array error: Omit includePaths, targetIds, or projectKeys when you want all items; passing [] is rejected by design to prevent accidental scope expansion.
  • Tray app closed: restic-tray.exe --mcp automatically falls back to headless local execution, so verify the executable path in your MCP client config matches your actual install path.

Startup error mentioning removed Google Drive backend

Cause: If migrating an older pre-1.0 config.json containing "storageBackend": "googleDrive", Restic Tray refuses to silently switch destinations.

Fix: Open %LOCALAPPDATA%\io.github.nayuengin.restic-tray\config.json, remove the "storageBackend": "googleDrive" line, configure your Cloudflare R2 settings, and restart. Existing Google Drive repositories remain standard restic repositories accessible directly with restic + rclone.
