Backup & Restore Procedures

Run dry-runs and encrypted backups, restore full or selective paths in the GUI, recover on a brand-new PC, or restore with the official restic CLI alone.

Restic Tray creates one encrypted snapshot per folder and never overwrites source folders during restore. All snapshots use the standard restic repository format and can be restored from the GUI, over MCP, on a new PC, or with the standalone restic CLI.

Restore methods, scope, and built-in safety guards
Method What You Need Safety Guard & Output Path
GUI Restore (Snapshots screen) Running Restic Tray configured with R2 credentials Restores into a separate folder validated by fs_safety; blocks drive roots (C:\), .. traversal, and Windows system paths; supports full or comma-separated partial paths.
MCP Restore (restore_snapshot) MCP client + agent.allowRestore: true (default) Restores full snapshot or explicit includePaths into a validated targetDir; rejects empty includePaths: [].
New PC Recovery Fresh Restic Tray install + R2 token + original repository password Re-enter identical Account ID, Bucket, Prefix, and external repository password; run 接続を確認 then restore.
Official restic CLI (without app) Official restic.exe + R2 keys + repository password Standard restic format with zero vendor lock-in; outputs under <target>\<DriveLetter>\<original\path>.

How to run your first backup (Dry-Run → Live)

  1. Open フォルダ (Folders) and verify all target folders and exclude settings (基本の除外パターンを有効にする).
  2. Return to 概要 (Overview) and click テスト実行 (Dry-Run). This executes restic backup --dry-run without uploading data so you can confirm file counts and check that caches/generated folders are excluded as expected.
  3. Click 今すぐバックアップ (Back up now) to perform the first real encrypted upload. Each enabled folder creates its own snapshot (1 target = 1 snapshot).
  4. Once verified, enable automatic scheduling under 設定 → スケジュール and verify your Windows Startup shortcut.

Restoring Data from the GUI

  1. Open スナップショット (Snapshots) and click R2 から読み込む (or 再読み込み) to load snapshots from Cloudflare R2.
  2. Select a snapshot on the left to inspect its metadata, browse files (ファイル一覧を表示), or compare changes against another snapshot (差分を表示).
  3. Under 復元 (Restore), choose a separate destination folder such as D:\Restore\2026-11-26. Restic Tray enforces fs_safety rules and rejects drive roots (C:\), unresolved reparse points, .. traversal, and Windows system paths (C:\Windows, C:\Program Files, etc.).
  4. Optional partial restore: Under 一部だけ復元する（任意）, enter comma-separated snapshot paths (for example /D/Projects/SampleWorld/notes) or leave blank to restore the full snapshot. Over MCP, pass includePaths to restore_snapshot.
  5. Click 復元する (Restore) and confirm in the dialog.
How restored paths are structured

Restic recreates the original drive-letter hierarchy inside your destination folder. For example, restoring a snapshot of D:\Projects\SampleWorld into D:\Restore\2026-11-26 places files under D:\Restore\2026-11-26\D\Projects\SampleWorld\.... Original folders are never overwritten in place.

Disaster Recovery on a New PC

If your PC fails, is lost, or Windows is freshly reinstalled:

  1. Install Restic Tray on the new Windows PC.
  2. Open 設定 → 保存先 (Storage) and enter the exact same Cloudflare R2 Account ID, Bucket, and Prefix, then click 保存.
  3. Open 設定 → 認証情報 (Credentials), enter valid R2 API credentials (you can issue a fresh API token in Cloudflare Dashboard at any time) and your exact original Restic repository password from your external password manager/backup, then click 認証情報を保存.
  4. Click 接続を確認 (Verify connection) to confirm access and repository integrity.
  5. Open スナップショット (Snapshots) and restore your files into a safe destination folder.

Recover Without Restic Tray (Official restic CLI)

Because Restic Tray writes a standard, unmodified Restic repository, you are never locked into this app. You can inspect and recover all data using only the official restic binary:

  1. Download the official Windows restic.exe from restic/restic Releases.
  2. Set your Cloudflare R2 S3 environment variables for the current PowerShell session:
PowerShell 
$env:AWS_ACCESS_KEY_ID = "<your-r2-access-key-id>"
$env:AWS_SECRET_ACCESS_KEY = "<your-r2-secret-access-key>"
$env:AWS_DEFAULT_REGION = "auto"
$env:RESTIC_REPOSITORY = "s3:https://<accountId>.r2.cloudflarestorage.com/<bucket>/<prefix>"
# Omit /<prefix> if your repository is stored at the bucket root.
Keep your repository password out of shell history

Leave $env:RESTIC_PASSWORD unset so restic.exe prompts you interactively instead of recording your password in PowerShell command history.

  1. List available snapshots and restore to a separate destination folder:
PowerShell 
.\restic.exe snapshots
.\restic.exe restore <snapshot-id> --target D:\Restore

Restored files appear under D:\Restore\<DriveLetter>\<original\path>\.... To verify repository integrity manually at any time, run .\restic.exe check --read-data-subset=5%.
