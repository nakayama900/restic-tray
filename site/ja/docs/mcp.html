MCP 統合（--mcp）

単一バイナリ内蔵の 22 ツール MCP サーバーを Claude Code・Cursor・Claude Desktop に登録し、安全に連携する手順と仕様です。

restic-tray.exe --mcp は単一バイナリに内蔵された Model Context Protocol (MCP) の stdio JSON-RPC 2.0 サーバーです。Claude Code・Claude Desktop・Cursor などの AI エージェントから、大規模変更前のバックアップ確認、テスト実行、差分確認、安全な復元を直接扱えます。

通信の仕組みと信頼境界

通信経路 
MCP クライアント
  ── stdio (JSON-RPC 2.0) ──▶ restic-tray.exe --mcp
  ── 名前付きパイプ (256-bit 相互認証) ──▶ 常駐トレイアプリ
  • トレイ常駐アプリ起動中: --mcp プロセスは %LOCALAPPDATA%\io.github.nayuengin.restic-tray\agent-bridge.json の一時パイプ名と 256-bit CSPRNG トークンで常駐アプリと定数時間認証し、ローカル名前付きパイプ（reject_remote_clients(true)）経由で要求を中継します。結果は即座に GUI と SQLite 監査ログへ反映されます。
  • ヘッドレスフォールバック: トレイ常駐アプリが未起動でも、--mcp がローカルコントローラへ自動フォールバックし、状態確認・設定変更・バックアップ実行を完遂できます。

MCP クライアントへの登録手順

Claude Code の場合

PowerShell 
claude mcp add --scope user restic-tray -- "$env:LOCALAPPDATA\Programs\Restic Tray\restic-tray.exe" --mcp

Claude Desktop / Cursor など（mcpServers JSON）

JSON 
{
  "mcpServers": {
    "restic-tray": {
      "command": "C:\\Users\\<ユーザー名>\\AppData\\Local\\Programs\\Restic Tray\\restic-tray.exe",
      "args": ["--mcp"]
    }
  }
}

Portable ZIP 版を使用している場合は、展開先の restic-tray.exe のパスを指定してください。

安全な初期設定と多段ガード

config.json の agent ポリシー既定値
  • 秘密情報の完全遮断: R2 キーやリポジトリパスワードは MCP で一切返却・受理せず、実行バイナリパス（resticBinaryPath）の変更も拒否します。
  • agent.enabled（既定: true）: MCP 操作全体の有効／無効スイッチ。
  • agent.allowRestore（既定: true）: restore_snapshot を許可します（fs_safety で検証された別フォルダへの復元であり、元の場所を上書きしません）。
  • agent.allowPrune（既定: false）: オプトイン制。false の間は forget_prune、update_retention_policy、autoPruneAfterBackup 有効化、maintenanceAt 変更、MCP 起点バックアップ後の自動 Prune をすべて抑止します。
  • agent.allowDeleteStorage（既定: false）: delete_r2_bucket のオプトイン制（dryRun: false と confirmBucketName 完全一致が必要）。
  • agent.allowHandoff（既定: false）: takeover_project のオプトイン制（dryRun: false と confirmProjectKey 完全一致が必要）。
  • 選択範囲の誤拡大防止: includePaths・targetIds・projectKeys に空配列 [] を渡すと「全体対象」へ広げず即座にエラーで拒否します。

全 22 ツールリファレンス

restic-tray.exe --mcp が提供する全 22 ツール一覧
ツール名 引数 説明
get_status なし 常駐状態、PC 名・保守担当、アクティブ対象件数、複数 PC 同期サマリー、R2・DPAPI 準備状況、同梱 restic 情報、次回実行予定、進捗、適用中の基本除外パターンを取得。
get_config なし 現在の非秘密 config.json（R2 設定、対象フォルダ、除外、スケジュール、保持ポリシー、agent ポリシー等）を取得。秘密情報は返しません。
get_backup_history limit?: number SQLite に保存されたバックアップ履歴（deferred、topAdded、bytesDelta、filesDelta、excludesChanged を含む）と監査ログを取得。
list_snapshots tag?, path?, projectKey?, host? R2 上のスナップショット一覧を取得。タグ・パス・共有 projectKey・小文字ホスト名での絞り込みに対応。
list_snapshot_files snapshotId, prefix?, maxEntries? 指定スナップショット内のファイル一覧を取得。
diff_snapshots snapshotA, snapshotB 2 つのスナップショット間の差分統計と変更パス一覧を取得。
get_size_breakdown snapshotId?, limit? 対象フォルダとその 2 階層下までの容量合計を大きい順に返却（省略時は最新、上限既定 30）。
run_backup targetIds?, projectKeys?, dryRun?, tags?, markHandoffReady? 対象ごと（1 対象 = 1 スナップショット）に R2 へバックアップ実行。dryRun: true や引き渡しタグ付与にも対応。
cancel_backup なし 実行中のバックアップ／引き継ぎ復元ジョブを即時キャンセル（--retry-lock 待機中も中断）。
init_repository なし 設定済みの R2 リポジトリを restic init で初期化。
check_repository readDataPercent?: number restic check で整合性検査。1–100 を指定すると保存データのその割合を読み戻して検証。
update_storage_config storageBackend?: "r2", r2?: object Cloudflare R2 の非秘密設定を検証して config.json に保存（秘密情報と resticBinaryPath の変更は拒否）。
add_backup_target path, label?, excludePatterns?, tags?, enabled?, projectKey?, writerState? 対象フォルダを正規化して追加・更新。.git を含むフォルダへの projectKey 付与は拒否。
remove_backup_target idOrPath: string 指定 ID またはパスのバックアップ対象を config.json から削除。
update_schedule enabled?, intervalMinutes?, dailyAt?, maintenanceAt?, runOnStartup?, autoPruneAfterBackup?, verifyEveryDays?, verifyReadPercent?, notifyOverdueHours? 定期スケジュール・定期復元確認・未実施通知を更新。Prune に影響する項目は agent.allowPrune: true が必要。
update_retention_policy keepLast?, keepDaily?, keepWeekly?, keepMonthly? スナップショット保持世代ポリシーを更新（agent.allowPrune: false のときは拒否）。
restore_snapshot snapshotId, targetDir, includePaths? 指定スナップショット全体または includePaths を安全な別フォルダ targetDir へ復元（既定有効: agent.allowRestore: true）。
forget_prune dryRun?, confirmPrune? オプトイン（agent.allowPrune: true）。既定 dryRun: true。本実行には dryRun: false と confirmPrune: true の両方が必要。
delete_r2_bucket scope: "prefixOnly"|"entireBucket", dryRun?, confirmBucketName? オプトイン（agent.allowDeleteStorage: true）。既定 dryRun: true。実削除には dryRun: false と confirmBucketName の完全一致が必要。
get_project_sync_status projectKey?, refresh?, checkLocalChanges? （実験的） 複数 PC 間の共有プロジェクト状態（local_latest / remote_newer / not_local / diverged / standby 等）を返却。
release_project projectKey, dryRun? （実験的） .git と UnityLockfile を検査し、handoff:released タグ付きバックアップ後に自 PC を standby へ移行（ローカルファイルは残る）。
takeover_project projectKey, localPath?, dryRun?, saveLocalBackupFirst?, confirmDiscardLocalChanges?, forceWhileRemoteActive?, deleteExtra?, confirmProjectKey? オプトイン（agent.allowHandoff: true、実験的）。既定 dryRun: true。本実行には confirmProjectKey の完全一致が必要。未保存変更は原則先に退避バックアップを作成。
