基本操作

トレイ常駐、フォルダ管理、Unity 対応の基本除外、定期スケジュール・復元確認、履歴と監査ログ、config.json の扱い方を解説します。

概要画面とタスクトレイ常駐

概要画面では、保護状態、最後に成功してからの経過時間、次の自動実行予定、有効な対象フォルダ数、保存先バケット、同梱 restic のバージョン、直近 7 日間の 1 時間単位グリッドをひと目で確認できます。

  • トレイへの格納: ウィンドウの閉じる（×）や最小化でタスクトレイに格納され、UI の描画ループが止まるため待機中の CPU 消費はほぼゼロに保たれます。
  • トレイメニューと多重起動防止: 右クリックメニューからウィンドウ表示・今すぐバックアップ・終了が行えます。2 回目の起動時は既存ウィンドウを前面表示して終了します。
  • ダーク / ライト 2 テーマ: サイドバー左下のアイコンまたは config.json（"theme": "dark" | "light"）で墨色・紙色のテーマを切り替えられます。

バックアップ対象フォルダの管理

フォルダ画面の フォルダを追加 ボタン、またはウィンドウへのドラッグ＆ドロップで対象フォルダを追加できます。バックアップは「1 対象 = 1 スナップショット」で作成されるため、スナップショット単位の確認や部分復元が見通しよく行えます。

対象パスは dunce::canonicalize で正規化されます。対象ごとの有効／無効切り替え、自由タグの付与（内部予約の project: / handoff: / excludes: 接頭辞は除く）、対象別の除外パターン指定に対応しています。

組み込みの基本除外と Unity 対応

初期状態で有効な 基本の除外パターンを有効にする（useBasicExcludes: true）により、再生成できるビルドキャッシュや一時ファイルだけを自動で外し、大切な作業データ（.git を含む）を効率よく守ります。

  • 全般の除外パターン（全階層で一致）: target/、node_modules/、.venv/、.pytest_cache/、__pycache__/、.git/objects/pack/tmp_pack_*、*.tmp、*.part、.next/、shadercompiler-*.log、AssetImportWorker*.log。
  • Unity プロジェクト直下の生成フォルダ（対象から 3 階層以内で ProjectSettings\ProjectVersion.txt を持つフォルダを自動検出し、その直下のみ除外）: Library、Temp、Logs、obj、Build、Builds、Assets\SerializedUdonPrograms。Assets/ や Packages/ 内の同名フォルダは除外されません。
  • 目印ファイルによる除外（excludeIfPresent）: SourceAssetDB、UnityLockfile、CACHEDIR.TAG（標準署名ヘッダ付き）、pyvenv.cfg を含むフォルダを自動で除外します。独自の目印も config.json へ追加できます。

誤って対象フォルダ丸ごとが除外されるのを防ぐため、いずれかの除外パターンが対象フォルダ自身のパスに一致する場合はバックアップ開始前に中止して案内します。生成物も含めて保存したい場合は、フォルダ画面で基本の除外パターンをオフにしてください。

スケジュール・定期復元確認・未実施通知

設定 → スケジュール または config.json で定期実行を制御します。

  • 間隔指定または毎日時刻指定: 既定は intervalMinutes: 60（60 分ごと）。dailyAt にローカル 24 時間表記の時刻配列（例: ["05:00", "17:00"]）を指定すると毎日その時刻に実行されます（dailyAt 指定時は間隔指定より優先）。起動時には 0–60 秒のジッターを入れて競合を避けます。
  • 定期的な復元確認: 既定で 7 日ごと（verifyEveryDays: 7、0 で無効）に保存データの 5%（verifyReadPercent: 5）を実際に読み戻して検証し（restic check --read-data-subset）、異常があれば Windows トースト通知で知らせます。
  • 未実施アラート通知: 成功が途絶えた時間が notifyOverdueHours（既定 48 時間、0 で無効）を超えると Windows トースト通知を出します。
  • 保持世代ポリシー（retention）: 既定は keepLast: 10、keepDaily: 7、keepWeekly: 4、keepMonthly: 6。バックアップ後の自動 Prune（autoPruneAfterBackup）は既定で無効です。有効化するか、maintenanceRole: "primary" の PC に maintenanceAt 枠を設けると安全に世代整理を実行します。

実行履歴・容量内訳・監査ログ

履歴画面では、ローカルの SQLite (WAL) データベース（r2_restic_history.db）に記録された履歴を確認できます。

  • バックアップタブ: 実行日時、実行元（定期・手動・MCP）、対象フォルダ、新規・変更件数、前回本番実行との増減（除外変更フラグ付き）、保存量、所要時間を一覧表示します。リポジトリの排他ロックで延期された実行は deferred として記録され、15 分後に最大 2 回自動再試行されます。
  • 操作ログタブ: 設定変更・バックアップ・復元・Prune・MCP からの呼び出しを監査ログとして残します。
  • 容量内訳: どのサブフォルダが容量を占めているかをアプリまたは MCP get_size_breakdown で確認できます。

config.json とデータ保存先

実行時データはすべてユーザーごとの %LOCALAPPDATA%\io.github.nayuengin.restic-tray\ 配下に置かれます。設定画面右上の config.json を開く から直接編集し、再読み込みすることもできます。

%LOCALAPPDATA%\io.github.nayuengin.restic-tray\ 配下の実行時ファイル
ファイル 役割
config.json 非秘密の設定（R2 保存先 r2、対象フォルダ targets、除外設定、schedule、retention、MCP ポリシー agent、テーマ）。
config\credentials.dat Windows DPAPI 暗号化済みの R2 アクセスキー ID・シークレットアクセスキー・Restic リポジトリパスワード。
r2_restic_history.db バックアップ履歴・GUI／トレイ／MCP の監査ログ・複数 PC 同期状態を記録する SQLite (WAL) データベース。
agent-bridge.json 常駐アプリ起動中のみ書き出される一時名前付きパイプ名と 256-bit 相互認証トークン。

安全な R2 削除と複数 PC 引き継ぎ

  • R2 プレフィックス／バケット削除: 設定 → 保存先 → バケット・データの削除（危険な操作） から、内蔵の純 Rust S3 クライアントでプレフィックス配下削除（prefixOnly）またはバケット全体の空化・削除（entireBucket）を実行できます。GUI では Dry-Run 事前集計・バケット名の手入力・1.5 秒長押しボタンによる多段ガードを備えています。
  • 複数 PC 共有プロジェクトと引き継ぎ （実験的機能）: Unity プロジェクトや素材フォルダなど Git 管理外の作業フォルダを複数 PC でやり取りする用途向けに、projectKey による単一ライター運用（引き渡す / この PC に取得して引き継ぐ）とサブパス読み替え復元・退避スナップショットを備えています。保守担当（maintenanceRole: "primary"）は 1 台のみに設定してください。.git を含むフォルダは引き継ぎ対象外です。
